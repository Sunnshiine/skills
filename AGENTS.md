# Agent rules for this repo

This repo is the single source of skills and agents for Claude Code and Codex. Upstream skills arrive through `vendor/<source>` branches that `tools/sync` writes; `main` is upstream plus the customizations logged in `CUSTOMIZATIONS.md`.

## Editing skills and agents

- Edit on `main`, under `skills/` and `agents/`. `vendor/*` branches are sync output; `tools/sync` rewrites them.
- Every change to a vendored skill or agent updates `CUSTOMIZATIONS.md` in the same commit: add a line under the item's `## <name>` heading, edit it, or delete it when the change is reverted or upstream adopts it. One line per change, changelog-terse.
- The block between the `renames` markers in `CUSTOMIZATIONS.md` is generated by `tools/sync`. Log a renamed skill's own customizations under its own heading above the block.
- Run `tools/install` to make changes live on this machine.

## Changing sources

Edit `sources.json`, then run `tools/sync <source>`. List order is precedence: on a name collision the earlier source keeps the bare name and the later one takes its `rename_prefix`. An `exclude` drops a skill before collisions are computed.

## Resolving a sync conflict

A conflict means upstream and a customization touched the same lines. Resolve each conflicted path so that:

1. Every customization in `CUSTOMIZATIONS.md` for that item still holds.
2. Every upstream change that does not contradict a customization is taken.
3. Where upstream made a customization obsolete (it adopted the change, or removed what the customization edits), `CUSTOMIZATIONS.md` drops or updates that line.

For a modify/delete conflict, upstream deleted an item that carries customizations: keep it only if a customization says the repo needs it, and otherwise delete it and its `CUSTOMIZATIONS.md` heading.

## Tests

`tools/sync.test` and `tools/install.test` build throwaway repos and homes and need no network. Run both after changing either tool.
