# Emil

Each skill lives at `../<name>/SKILL.md` from this file. Pick every skill whose entry matches the task, read each one's SKILL.md in full, and follow it. Run build skills before review skills.

## Build

- **animate.** Building new web motion: a transition, an entrance, a component that should feel alive.
- **animate-expo.** Any motion in React Native or Expo: gestures, sheets, screen transitions, press feedback, haptics.
- **apple-design.** Apple-style fluid UI on the web: springs, drag, swipe and sheet gestures, momentum, materials, typography.
- **mobile-native.** A web app that must feel installed on a phone: 100vh, input zoom, tap highlights, the notch, PWAs, touch.
- **prototype.** The user wants several distinct versions of a UI piece to flip between live and pick one.
- **ask-sonner.** Setting up or troubleshooting Sonner toasts.
- **pick-ui-library.** Choosing a library for a frontend job: charts, OTP inputs, command menus, drag and drop, virtualization.
- **write-swift.** Writing, reviewing, or migrating Swift.

## Review and fix

- **emil-design-eng.** Polishing or critiquing UI craft: component details, easing, springs, transforms, clip-path. The general taste reference.
- **review-animations.** Reviewing a specific diff or file of animation code against a strict bar.
- **animation-performance.** Web motion that janks or drops frames, or picking properties to fit the frame budget.
- **break-ui.** Stress-testing a component with worst-case data: long names, empty states, huge counts, emoji.

## Audit (read-only)

- **improve-animations.** Auditing a whole codebase's motion into a prioritized plan for other agents to execute.
- **find-animation-opportunities.** Finding places that don't animate but should.

## Reference

- **animation-vocabulary.** The user describes a motion effect and needs its name.
