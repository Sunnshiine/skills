# Emil router

Match the task to every branch below it touches, then invoke those skills in order: build before review. Each row names only what tells a skill apart from its neighbours; the skill's own description carries the rest.

## Invoke with the Skill tool

| Branch | Skill |
| --- | --- |
| Build new web motion | `animate` |
| Build motion in React Native or Expo | `animate-expo` |
| Web motion drops frames, or a property choice is about frame budget | `animation-performance` |
| Name a motion effect the user describes | `animation-vocabulary` |
| Apple-style gestures, springs, materials, typography | `apple-design` |
| Sonner toasts | `ask-sonner` |
| Stress-test a component with worst-case data | `break-ui` |
| Polish or critique UI and existing motion | `emil-design-eng` |
| Find what should animate but doesn't (read-only) | `find-animation-opportunities` |
| Audit a codebase's motion into a fix plan (read-only) | `improve-animations` |
| Web app that must feel native on a phone | `mobile-native` |
| Swift | `write-swift` |

## Ask the user to type these

These skills refuse the Skill tool. When one matches, stop and name the command for the user to run.

| Branch | Command |
| --- | --- |
| Strict review of animation code, where `emil-design-eng` is the lighter default | `/review-animations` |
| Several UI variants behind a live picker | `/prototype` |
| Choose a frontend library | `/pick-ui-library` |
