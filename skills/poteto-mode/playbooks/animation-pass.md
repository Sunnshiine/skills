### Animation pass

Each skill's Initial Response stub waits for a question, so invoke each with its input in the same turn.

1. Run **find-animation-opportunities** on the surface the user named, or the whole app if they named none.
2. Build each surviving row with **animate**, one commit per row, instead of the finder's `improve-animations plan` handoff.
3. Review the diff in a fresh `poteto-agent` that reads `review-animations/SKILL.md` and its `STANDARDS.md` in full, by path from the skill folders in **Harness**, since the skill is `disable-model-invocation`. On Block, fix the findings with **animate** and re-review in a fresh one, stopping on Approve or after three Block rounds.
4. Feel-check each animation on the running surface, slowed to 2–5× duration and again with `prefers-reduced-motion` on. Capture a recording or frame sequence per row.
5. Run **Opening a PR**.

**Reply:** the rows built, rows rejected by either gate and why, the review verdict and rounds, open findings, captures per row, and the feel checks left for the user.
